# Helion Code Map: `com.aryston.helion.render.rtx`

Part of the [Helion code map](../CODEMAP.md). Every class of this package has its entry here and nowhere else (rule D1).

### `com.aryston.helion.render.rtx`

Hardware ray tracing on Minecraft's Vulkan device: ray tracing with water reflections (experimental setting `rayTracing.enabled`, or `-Dhelion.rayTracing=true`, see `docs/architecture/ray-tracing.md`) and the RTX feasibility spike (`-Dhelion.rtxSpike=true`, see `docs/architecture/voxel-lighting.md`). With the setting off and neither property set, no class but the switches loads, the device is created as before and every stage returns in `isActive`. This is the only Helion code that uses renderpearl backend types (`VulkanDevice`, `VulkanCommandEncoder`, `VulkanGpuTextureView`) and raw Vulkan, the exception to invariant 2.

#### RayTracing, RayTracingSettings, RtxSpike
- Path: `src/main/java/com/aryston/helion/render/rtx/RayTracing.java`, `src/main/java/com/aryston/helion/render/rtx/RayTracingSettings.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSpike.java`
- Role: The switches: `RayTracing.requested()` (the `rayTracing.enabled` setting read at startup by `RayTracingStartup`, or forced by `helion.rayTracing`), `forced()`, `VIEW` (`helion.rayTracing.view`, runs and draws the traced sun shadow), the per-frame `RayTracingSettings` (`active()` when the setting is on and the device was requested, `reflectsWater()`, `tracesShadows()`), `RtxSpike.ENABLED` (`helion.rtxSpike`) and `VIEW` (`helion.rtxSpike.view`), `RayTracing.deviceRequested()` when either asks for the ray query device features, and the extra texture usage bit `TEXTURE_USAGE_STORAGE` that `VulkanConstMixin` turns into `VK_IMAGE_USAGE_STORAGE_BIT`.

#### RtxFeature
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxFeature.java`
- Role: The optional renderpearl `FeatureSet` "Helion ray query spike": `VK_KHR_acceleration_structure`, `VK_KHR_ray_query`, `VK_KHR_deferred_host_operations` with `bufferDeviceAddress`, `accelerationStructure` and `rayQuery`. Renderpearl enables it only when the device supports all of it, so other cards start as before. `ENTITY_TEXTURES` is a second optional set with only `shaderSampledImageArrayNonUniformIndexing`, which entity textures in ray traced reflections need; without it reflections stay terrain only.

#### RtxDevice
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxDevice.java`
- Role: The Vulkan device behind renderpearl when it enabled `RtxFeature`: its VMA allocator, scratch and storage buffer alignments, whether `RtxFeature.ENTITY_TEXTURES` is enabled (`entityTextures`), renderpearl's current command buffer and its full memory barrier.
- Depends on: `FrontendGpuDeviceAccessor`, `VulkanDeviceAccessor`, `VulkanCommandEncoderAccessor`.

#### RtxBuffer
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxBuffer.java`
- Role: A buffer from renderpearl's VMA allocator (which `VulkanBackendMixin` creates with buffer device addresses when the ray tracing features are on) with the shader device address usage, device local or mapped host coherent, and its device address.

#### RtxGeometry, RtxAccelerationStructure
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxGeometry.java`, `src/main/java/com/aryston/helion/render/rtx/RtxAccelerationStructure.java`
- Role: Input of one acceleration structure (unit boxes, indexed `R32G32B32_SFLOAT` triangles or instances) and the structure itself: storage buffer, opaque geometry (entity draws are not opaque), prefer fast trace, with its own scratch buffer or built with a shared one, recorded into a command buffer; the top level is rebuilt from a new instance address every frame.

#### RtxSectionUpdate, RtxSectionPos, RtxSectionInbox
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxSectionUpdate.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionPos.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionInbox.java`
- Role: The thread-safe hand-over from the section compile workers: a compiled section's solid and cutout quad positions relative to the section (or a removal), section coordinates with Chebyshev distance, and the queue that accepts sections within `RADIUS` (4) plus one section of the last camera section and hands recompile requests back to the integration. Each update also carries three ints per vertex for reflections (`SURFACE_INTS_PER_VERTEX`): the atlas texture coordinate as two 16-bit fractions, the vertex color as RGBA8 and the block and sky light coordinates as two bytes. It also counts the solid quads, which come before the cutout quads.

#### RtxQuadIndices, RtxSharedScratch, RtxSectionBlas
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxQuadIndices.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSharedScratch.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionBlas.java`
- Role: The shared quad index buffer (two triangles per four vertices, grown to the largest section), the shared build scratch buffer (grown to the builds of one frame) and the bottom level structure of one section: its vertex buffer lives only until the build is recorded. A section also keeps its surface attributes in a device local storage buffer, uploaded through a mapped staging buffer that is copied while the bottom level is recorded and then released; `surfaceAddress()` is its device address. Each bottom level has two geometries over one vertex buffer: the solid quads, opaque, and the cutout quads (leaves, plants, glass panes of the cutout layer), not opaque, so ray queries alpha test them against the atlas.

#### RtxTopLevel, RtxScenePlan, RtxSectionScene, RtxSceneStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxTopLevel.java`, `src/main/java/com/aryston/helion/render/rtx/RtxScenePlan.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionScene.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSceneStage.java`
- Role: The section scene around the camera. Every frame `RtxSceneStage` (after the opaque geometry) drains the inbox, drops sections more than 2 sections outside the radius, builds up to 16 bottom levels nearest first, asks for at most 8 recompiles of sections in the radius that never arrived, and rebuilds the top level (up to 1024 instances in a ring of four mapped instance buffers, translated relative to the camera section, triangle culling off) in a frame graph pass without culling (`rt_bottom_levels`, `rt_top_level`). The custom index of every instance is its slot, and a ring of four mapped surface tables (`surfaceTable()`) holds the surface buffer address of the section in each slot, so a shader can read the texture coordinate, color and light of any hit. A surface table entry is 16 bytes: the buffer address and the number of solid quads, which places the cutout primitives after them. Section instances use ray mask 1. The entity bottom level is appended at record time as two instances, both translated by the camera position relative to the anchor section: one with mask 2 forced opaque for shadows (which trace masks 1 and 2), one with mask 4, forced non-opaque and custom index `0xFFFFFF`, for reflections, which alpha test entity candidates against their own texture.

#### RtxBinding, RtxComputePipeline, RtxShaderSource
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxBinding.java`, `src/main/java/com/aryston/helion/render/rtx/RtxComputePipeline.java`, `src/main/java/com/aryston/helion/render/rtx/RtxShaderSource.java`
- Role: A raw compute pipeline from a `.csh` resource (includes expanded in Java, compiled by shaderc for Vulkan 1.2 and SPIR-V 1.5) with optional shader defines, push descriptors described by `RtxBinding` (storage image, acceleration structure, storage buffer, sampled image or sampled image array with the pipeline's nearest sampler; a binding can hold several descriptors) and push constants. `include/helion_rt_surface.glsl` reads the surface of a committed or candidate hit from the section surface table and `helionTraceCutout` confirms a candidate cutout triangle only where the atlas alpha is at least 0.5. `include/helion_rt_entity.glsl` reads an entity hit (indices, color, UV0 and light straight from the staged buffers through buffer references), shades it with the vanilla entity lights (two fixed directions, 0.4 ambient plus 0.6 diffuse) from its normal and applies the hurt and white flash overlay from UV1 the way `OverlayTexture` lays it out, and alpha tests entity candidates at 0.1 like vanilla.

#### RtxImage, RtxMaskPipelines, RtxMaskViewStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxImage.java`, `src/main/java/com/aryston/helion/render/rtx/RtxMaskPipelines.java`, `src/main/java/com/aryston/helion/render/rtx/RtxMaskViewStage.java`
- Role: An RGBA8 renderpearl texture with the storage usage bit (half resolution for the masks, full resolution for the reflections), and the last stage that draws a mask over the output: the spike view (`rtx/mask_view.fsh`) or the traced sun shadow (`rtx/sun_shadow_view.fsh`, blocked pixels dark blue).

#### RayTracingResources, RtxShadowTracer
- Path: `src/main/java/com/aryston/helion/render/rtx/RayTracingResources.java`, `src/main/java/com/aryston/helion/render/rtx/RtxShadowTracer.java`
- Role: Owned by `HelionRenderCore`. Opens the device, the section scene and the sun shadow pipeline on first use (logs once and stays off when the device has no ray queries) and logs the scene size, CPU and GPU times when the scene first completes and every 600 frames as `Helion ray tracing`. `RtxShadowTracer` is the `TracedShadows` of `ShadowStage`: with ray traced shadows on (or the validation view), pass `rt_sun_shadow` traces four rays per half resolution pixel within the scene toward the sun or moon, spread over a cone of 0.012 radians around the stepped light direction and rotated per pixel by interleaved gradient noise, with `rtx/sun_shadow.csh`, and writes visibility, its weight (decided rays, faded over the last 8 blocks of the scene) and a traced flag into the mask image. A ray that leaves the scene through a side counts as undecided, so a hill outside the scene still shades through the shadow map; leaving through the top counts as lit. It also creates the reflection pipeline (`rtx/reflection.csh`; when it does not compile only reflections stay off), the full resolution reflection image and its push constants. `suspend()` releases the scene and images when the setting is turned off during a session (`RtxSceneStage` calls it every inactive frame) and the next active frame builds a new scene; the device features stay.

#### RtxEntityDraws, RtxEntityScene
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxEntityDraws.java`, `src/main/java/com/aryston/helion/render/rtx/RtxEntityScene.java`
- Role: The entities of the frame in the ray tracing scene. `RtxSceneStage` switches capturing on while ray traced shadows run or ray traced reflections can show entities (`RtxDevice.entityTextures`); `RtxEntityDraws` collects the renderpearl vertex and index buffers, base vertex, index offset and triangle count of every entity draw of the geometry pass, plus its `Sampler0` image view and the offsets of its color, UV0 and light attributes (`Surface`); `RtxEntityScene` turns them into one bottom level with one geometry per draw, read in place from the staged buffers (camera relative positions), built for fast builds with updates allowed. When the draws have the same shape as last frame it only updates the structure, with a full rebuild every 30 frames; it is recreated with twice the room when it no longer fits. Its geometries are not opaque, so reflections can alpha test them. It owns `RtxEntitySurfaces`, written with the same draws every frame (and emptied when nothing is captured).
- Depends on: `RtxAccelerationStructure`, `RtxGeometry`, `GpuResources`.

#### RtxEntitySurfaces
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxEntitySurfaces.java`
- Role: Per frame entity hit table for ray traced reflections, in a ring of four mapped storage buffers (2048 draws): a 16-byte header with the draw count, then 48 bytes per entity geometry (vertex and index buffer addresses, base vertex, stride, the color, UV0 and light offsets with a 16-bit index flag, the texture slot, the index byte offset, the normal and overlay offsets). Gives each distinct entity texture one of 16 slots; draws past 16 textures or with unreadable attributes get no slot and stay out of reflections (they still cast shadows). `views(fallback)` fills the unused slots with a fallback view for the descriptor array. Read by `include/helion_rt_entity.glsl`.
- Depends on: `RtxBuffer`, `RtxEntityDraws`, `GpuResources`.

#### RtxReflectionStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxReflectionStage.java`
- Role: Pass `rt_reflection` after the water surface: for every water pixel and every glossy translucent pixel (glass, ice) inside the section scene, reflects the view ray at the wave normal and traces it up to 96 blocks with `rtx/reflection.csh`. A hit is shaded with the block atlas texel at the interpolated texture coordinate, the vertex color and the vanilla lightmap at the interpolated light coordinates and written with alpha 1; a shadow ray from the hit toward the sun (the moon when the sun is down; the direction comes from the physical sky, else no ray) scales the sky light coordinate to 0.55 when it is blocked; when the device enabled `RtxFeature.ENTITY_TEXTURES` the shader is compiled with `HELION_RT_ENTITIES`, also traces the entity reflection instance and shades entity hits the same way from their own texture (16-slot sampler array and the `RtxEntitySurfaces` table, bindings 7 and 8); a miss writes alpha 0 so the water composite uses the sky. Publishes the image in `WaterResults`.
- Depends on: `RayTracingResources`, `RtxSectionScene`, `RtxEntitySurfaces`, `RtxComputePipeline`, `RtxImage`, `TerrainSource`, `WaterResults`.

#### RtxArea, RtxBlocks, RtxScene, RtxAgreement, RtxTraceMode, RtxSpikeResources, RtxShadowStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxArea.java`, `src/main/java/com/aryston/helion/render/rtx/RtxBlocks.java`, `src/main/java/com/aryston/helion/render/rtx/RtxScene.java`, `src/main/java/com/aryston/helion/render/rtx/RtxAgreement.java`, `src/main/java/com/aryston/helion/render/rtx/RtxTraceMode.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSpikeResources.java`, `src/main/java/com/aryston/helion/render/rtx/RtxShadowStage.java`
- Role: The RTX spike: a CPU copy of the voxel volume, unit boxes of the exposed light-blocking blocks of the 3 x 3 chunks around the camera in one bottom and one top level, and the `rtx/shadow_mask.csh` pass after `voxel_light` that traces the brightest light of each pixel with ray queries and with the voxel grid walk in rotating modes (`rtx_ray_query`, `rtx_grid_walk`, `rtx_compare`) and counts their agreement.
- Depends on: `RtxSpikeResources`, `VoxelLightingResources`.
