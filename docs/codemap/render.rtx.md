# Helion Code Map: `com.aryston.helion.render.rtx`

Part of the [Helion code map](../CODEMAP.md). Every class of this package has its entry here and nowhere else (rule D1).

### `com.aryston.helion.render.rtx`

Hardware ray tracing on Minecraft's Vulkan device: ray tracing with water reflections and the path traced light (experimental settings `rayTracing.enabled` and `rayTracing.pathTracing`, or `-Dhelion.rayTracing=true`, see `docs/architecture/ray-tracing.md` and `docs/architecture/path-tracing.md`). Helion's old light and shadow passes were removed on 2026-10-27 and are rebuilt as path tracing; the old passes live on the branch `archive/voxel-lighting` (tag `lighting-v1`). With the setting off and the property not set, no class but the switches loads, the device is created as before and every stage returns in `isActive`. This is the only Helion code that uses renderpearl backend types (`VulkanDevice`, `VulkanCommandEncoder`, `VulkanGpuTextureView`) and raw Vulkan, the exception to invariant 2.

#### RayTracing, RayTracingSettings
- Path: `src/main/java/com/aryston/helion/render/rtx/RayTracing.java`, `src/main/java/com/aryston/helion/render/rtx/RayTracingSettings.java`
- Role: The switches: `RayTracing.requested()` (the `rayTracing.enabled` setting read at startup by `RayTracingStartup`, or forced by `helion.rayTracing`), which also asks for the ray query device features, `forced()`, and the per-frame `RayTracingSettings` (`active()` when the setting is on and the device was requested, `reflectsWater()`, `tracesLight()` when `pathTracing` is on too).

#### RtxFeature
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxFeature.java`
- Role: The optional renderpearl `FeatureSet` "Helion ray query spike": `VK_KHR_acceleration_structure`, `VK_KHR_ray_query`, `VK_KHR_deferred_host_operations` with `bufferDeviceAddress`, `accelerationStructure` and `rayQuery`. Renderpearl enables it only when the device supports all of it, so other cards start as before. `ENTITY_TEXTURES` is a second optional set with only `shaderSampledImageArrayNonUniformIndexing`, which entity textures in ray traced reflections need; without it reflections stay terrain only.

#### RtxDevice
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxDevice.java`
- Role: The Vulkan device behind renderpearl when it enabled `RtxFeature`: its VMA allocator, scratch and storage buffer alignments, whether `RtxFeature.ENTITY_TEXTURES` is enabled (`entityTextures`), renderpearl's current command buffer and its full memory barrier.
- Depends on: `FrontendGpuDeviceAccessor`, `VulkanDeviceAccessor`, `VulkanCommandEncoderAccessor`.

#### RtxBuffer
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxBuffer.java`
- Role: A buffer from renderpearl's VMA allocator (which `VulkanBackendMixin` creates with buffer device addresses when the ray tracing features are on) with the shader device address usage, device local or mapped host coherent, and its device address.

#### RtxGeometry, RtxAccelerationStructure
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxGeometry.java`, `src/main/java/com/aryston/helion/render/rtx/RtxAccelerationStructure.java`
- Role: Input of one acceleration structure (indexed `R32G32B32_SFLOAT` triangles or instances) and the structure itself: storage buffer, opaque geometry (entity draws are not opaque), prefer fast trace, with its own scratch buffer or built with a shared one, recorded into a command buffer; the top level is rebuilt from a new instance address every frame.

#### RtxSectionUpdate, RtxSectionPos, RtxSectionInbox, RtxSectionKey
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxSectionUpdate.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionPos.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionInbox.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionKey.java`
- Role: The thread-safe hand-over from the section compile workers: a compiled section's solid and cutout quad positions relative to the section (or a removal), section coordinates with Chebyshev distance, and the queue that accepts sections within `RADIUS` (4) plus one section of the last camera section and hands recompile requests back to the integration. Each update also carries four ints per vertex (`SURFACE_INTS_PER_VERTEX`): the atlas texture coordinate as two 16-bit fractions, the vertex color as RGBA8, the block and sky light coordinates as two bytes and the face normal of its quad (cross product of the two diagonals) in octahedral form as two signed 16-bit values; the sign follows the vertex winding, so shaders turn it toward the ray. It also counts the solid quads, which come before the cutout quads, and carries the block lights of the section (`LIGHT_INTS`, eight ints per light, see `RtxSectionLights`). `RtxSectionKey` holds the section size of 16 blocks, the section of a block coordinate and the packed 64-bit key of a section (22 bits for X and Z, 20 for Y) with its decoders.

#### RtxQuadIndices, RtxSharedScratch, RtxSectionBlas
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxQuadIndices.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSharedScratch.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionBlas.java`
- Role: The shared quad index buffer (two triangles per four vertices, grown to the largest section), the shared build scratch buffer (grown to the builds of one frame) and the bottom level structure of one section: its vertex buffer lives only until the build is recorded. A section also keeps its surface attributes in a device local storage buffer, uploaded through a mapped staging buffer that is copied while the bottom level is recorded and then released; `surfaceAddress()` is its device address. Each bottom level has two geometries over one vertex buffer: the solid quads, opaque, and the cutout quads (leaves, plants, glass panes of the cutout layer), not opaque, so ray queries alpha test them against the atlas.

#### RtxTopLevel, RtxScenePlan, RtxSectionScene, RtxSceneStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxTopLevel.java`, `src/main/java/com/aryston/helion/render/rtx/RtxScenePlan.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSectionScene.java`, `src/main/java/com/aryston/helion/render/rtx/RtxSceneStage.java`
- Role: The section scene around the camera. Every frame `RtxSceneStage` (after the opaque geometry) drains the inbox, drops sections more than 2 sections outside the radius, builds up to 16 bottom levels nearest first, asks for at most 8 recompiles of sections in the radius that never arrived, and rebuilds the top level (up to 1024 instances in a ring of four mapped instance buffers, translated relative to the camera section, triangle culling off) in a frame graph pass without culling (`rt_bottom_levels`, `rt_top_level`). The custom index of every instance is its slot, and a ring of four mapped surface tables (`surfaceTable()`) holds the surface buffer address of the section in each slot, so a shader can read the texture coordinate, color and light of any hit. A surface table entry is 16 bytes: the buffer address and the number of solid quads, which places the cutout primitives after them. Section instances use ray mask 1. The entity bottom level is appended at record time as two instances, both translated by the camera position relative to the anchor section: one with mask 2 forced opaque for shadow rays (which trace masks 1 and 2), one with mask 4, forced non-opaque and custom index `0xFFFFFF`, for reflections, which alpha test entity candidates against their own texture. `RtxSectionScene` also hands the block lights of every built, emptied, removed and dropped section to its `RtxLightScene` and writes its grid after the top level (`lightBuffer()`).

#### RtxLightScene
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxLightScene.java`
- Role: The block lights of the section scene for the path traced light. Keeps the light records of every section and, when they changed or the anchor moved, rebuilds a grid of 9x9x9 section cells around the anchor: each cell lists up to 32 lights of its own and its 26 neighbor sections, nearest sections first, with the boxes moved to anchor relative coordinates. Written every frame to the next of a ring of four mapped storage buffers (`buffer()`): 729 cell headers (first record, count) followed by two uvec4 per record.
- Depends on: `RtxBuffer`, `RtxSectionUpdate`, `RtxSectionKey`, `GpuResources`.

#### RtxBinding, RtxComputePipeline, RtxShaderSource
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxBinding.java`, `src/main/java/com/aryston/helion/render/rtx/RtxComputePipeline.java`, `src/main/java/com/aryston/helion/render/rtx/RtxShaderSource.java`
- Role: A raw compute pipeline from a `.csh` resource (includes expanded in Java, compiled by shaderc for Vulkan 1.2 and SPIR-V 1.5) with optional shader defines, push descriptors described by `RtxBinding` (storage image, acceleration structure, storage buffer, sampled image or sampled image array with the pipeline's nearest sampler; a binding can hold several descriptors) and push constants. `include/helion_rt_surface.glsl` reads the surface of a committed or candidate hit (texture coordinate, tint, light and face normal) from the section surface table and `helionTraceCutout` confirms a candidate cutout triangle only where the atlas alpha is at least 0.5. `include/helion_rt_entity.glsl` reads an entity hit (indices, color, UV0 and light straight from the staged buffers through buffer references), shades it with the vanilla entity lights (two fixed directions, 0.4 ambient plus 0.6 diffuse) from its normal and applies the hurt and white flash overlay from UV1 the way `OverlayTexture` lays it out, and alpha tests entity candidates at 0.1 like vanilla.

#### RtxImage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxImage.java`
- Role: A renderpearl texture (RGBA8 by default, any format on request) with the storage usage bit `TEXTURE_USAGE_STORAGE`, which `VulkanConstMixin` turns into `VK_IMAGE_USAGE_STORAGE_BIT`, so a compute shader writes it and a fragment shader samples it; the reflections use one at full resolution.

#### RtxDenoiseImages
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxDenoiseImages.java`
- Role: The full resolution RGBA16F images of the path traced light, owned by `RayTracingResources` and recreated when the scene size changes: two work images (the traced irradiance and the accumulated, then filtered result), the filtered history, and a pair each of moments (luminance mean, mean square, sample count) and guides (normal and view distance, negative for emissive pixels), plus the traced specular radiance and a pair of accumulated specular histories (sample count in alpha) that swap every frame. It keeps the last level view projection and camera position; `reprojection(camera)` returns that matrix translated by the camera move (zero before the first frame) and `advance` swaps the pairs and stores the current camera.
- Depends on: `RtxImage`, `GpuResources`, `HelionCamera`.

#### RtxLightCache
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxLightCache.java`
- Role: The world space face light cache of the path traced light. A device local hash table of 2^18 entries of 64 bytes (check, last requested frame, sample count, face and level; face plane, cell column and row; indirect light and sky gate; the sample position inside the cell) and two update queues of 512 x 256 cells, cleared with a buffer fill on first use. `advance()` swaps the queue the trace fills with the one the update reads. Created by `RayTracingResources.lightCache()` on first use.
- Depends on: `RtxBuffer`, `RtxBinding`, `GpuResources`.

#### RayTracingResources
- Path: `src/main/java/com/aryston/helion/render/rtx/RayTracingResources.java`
- Role: Owned by `HelionRenderCore`. Opens the device and the section scene on first use (logs once and stays off when the device has no ray queries) and logs the scene size, CPU and GPU times (bottom levels, top level, path tracing, denoising, reflections) when the scene first completes and every 600 frames as `Helion ray tracing`. It creates the reflection pipeline (`rtx/reflection.csh`) and the path tracing pipelines (`rtx/path_trace.csh`, `rtx/denoise_accumulate.csh`, `rtx/denoise_filter.csh`, `rtx/specular_accumulate.csh` plus the light cache update, all or none); when one does not compile only its pass stays off, the device and the scene still open. It also holds the full resolution reflection image with its push constants and the path traced light: the `RtxDenoiseImages` at the scene size and the push constants of the trace (128 bytes), the accumulation (128 bytes) and the filter (16 bytes). It also counts the path traced frames (`nextPathTraceFrame()`, the frame counter and random seed of the trace, kept here because the stages are created anew every frame), records whether the path traced light ran in the last frame (`pathTraced()`, set by `RtxPathTracingStage.isActive`) and owns `RtxLightCache` and its update pipeline (`path_trace.csh` with `HELION_LIGHT_CACHE_UPDATE`). `suspend()` releases the scene and images when the setting is turned off during a session (`RtxSceneStage` calls it every inactive frame) and the next active frame builds a new scene; the device features stay.

#### RtxEntityDraws, RtxEntityScene
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxEntityDraws.java`, `src/main/java/com/aryston/helion/render/rtx/RtxEntityScene.java`
- Role: The entities of the frame in the ray tracing scene. `RtxSceneStage` switches capturing on while ray traced reflections can show entities (`RtxDevice.entityTextures`); `RtxEntityDraws` collects the renderpearl vertex and index buffers, base vertex, index offset and triangle count of every entity draw of the geometry pass, plus its `Sampler0` image view and the offsets of its color, UV0 and light attributes (`Surface`); `RtxEntityScene` turns them into one bottom level with one geometry per draw, read in place from the staged buffers (camera relative positions), built for fast builds with updates allowed. When the draws have the same shape as last frame it only updates the structure, with a full rebuild every 30 frames; it is recreated with twice the room when it no longer fits. Its geometries are not opaque, so reflections can alpha test them. It owns `RtxEntitySurfaces`, written with the same draws every frame (and emptied when nothing is captured).
- Depends on: `RtxAccelerationStructure`, `RtxGeometry`, `GpuResources`.

#### RtxEntitySurfaces
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxEntitySurfaces.java`
- Role: Per frame entity hit table for ray traced reflections, in a ring of four mapped storage buffers (2048 draws): a 16-byte header with the draw count, then 48 bytes per entity geometry (vertex and index buffer addresses, base vertex, stride, the color, UV0 and light offsets with a 16-bit index flag, the texture slot, the index byte offset, the normal and overlay offsets). Gives each distinct entity texture one of 16 slots; draws past 16 textures or with unreadable attributes get no slot and stay out of reflections. `views(fallback)` fills the unused slots with a fallback view for the descriptor array. Read by `include/helion_rt_entity.glsl`.
- Depends on: `RtxBuffer`, `RtxEntityDraws`, `GpuResources`.

#### RtxReflectionStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxReflectionStage.java`
- Role: Pass `rt_reflection` after the water surface: for every water pixel and, where the water target is empty, every glass pixel (glass surface and depth at bindings 10 and 11) inside the section scene, reflects the view ray at the wave normal and traces it up to 96 blocks with `rtx/reflection.csh`. A hit is shaded with the block atlas texel at the interpolated texture coordinate, the vertex color and the vanilla lightmap at the interpolated light coordinates and written with alpha 1; a shadow ray from the hit, lifted along its face normal (against the ray direction for entities), toward the sun (the moon when the sun is down; the direction comes from the physical sky, else no ray) scales the sky light coordinate to 0.55 when it is blocked; when the device enabled `RtxFeature.ENTITY_TEXTURES` the shader is compiled with `HELION_RT_ENTITIES`, also traces the entity reflection instance and shades entity hits the same way from their own texture (16-slot sampler array and the `RtxEntitySurfaces` table, bindings 7 and 8); a miss writes alpha 0 so the water composite uses the sky. Runs before `ssr`; while rain puddles are published it also traces geometry buffer pixels whose puddle is above 0.05 (scene depth, geometry normal and light at bindings 7 to 9, entity bindings move to 12 and 13), which `ssr` uses where its march misses. Publishes the image in `WaterResults`.
- Depends on: `RayTracingResources`, `RtxSectionScene`, `RtxEntitySurfaces`, `RtxComputePipeline`, `RtxImage`, `TerrainSource`, `WaterResults`.


#### RtxPathTracingStage
- Path: `src/main/java/com/aryston/helion/render/rtx/RtxPathTracingStage.java`
- Role: The path traced light, right after `RtxSceneStage` where deferred shading used to run; only with `RayTracingSettings.tracesLight()`, the geometry buffer written, an RGBA8 scene and the path trace pipeline compiled. Pass `path_trace` (culling off) dispatches `rtx/path_trace.csh` into the first work image of `RtxDenoiseImages`: every geometry buffer pixel gets demodulated linear HDR irradiance (the light before the surface albedo), with a signal in alpha (0 no geometry, 1 lit, 2 emissive). It also needs the physical sky light (`SkyLight`) and a scene anchor. The irradiance is light in linear units anchored to vanilla (open ground under the full sky equals the vanilla full sky light linearized, L-175): one shadow ray each to a soft disk of the sun and the moon, one cosine sampled path of up to 3 bounces for indirect light (see `docs/architecture/path-tracing.md`), and the block lights of the pixel's cell in the `RtxLightScene` grid, where the brightest light and one light picked in proportion to the rest get a shadow ray that ends where it enters the light's box (L-174); the rest adds a saturating share (L-171). The albedo is divided by the vanilla directional shade; emissive and lava pixels write 1, and pixels near the scene edge blend to the vanilla light divided by the albedo. The material mask (`GlossyMask`) is bound so bounce hits on emissive texels end the path. Push constants (128 bytes): the inverse view projection, the camera relative to the anchor with the time, the sun and moon directions with an above horizon flag, and the anchor section with a frame counter (also the random seed). With the light cache (`RtxLightCache`) the pass first dispatches `path_trace.csh` with `HELION_LIGHT_CACHE_UPDATE` over the cells queued last frame (one indirect path per cell, four while it has fewer than 8 samples, blended up to 64 samples), then the trace, where pixels with axis aligned normals take the indirect light from the bilinear blend of their face cells and queue their own cell. Glossy and metal pixels also get a specular signal in a second RGBA16F image (binding 15): the sun and moon through an analytic GGX lobe with a shadow ray, plus one GGX (visible normal) sampled reflection ray whose hit is shaded like a last bounce (emissive texels at their own color) and whose miss reads the sky map rows of the sky light target, weighted by Fresnel and masking and limited to luminance 8; see `docs/architecture/path-tracing.md`. Pass `path_denoise` (culling off) runs `rtx/denoise_accumulate.csh` (temporal accumulation: reprojects the history with the previous view projection, keeps it where the guide distance and normal match, blends up to 24 samples, tracks the luminance moments and writes the variance in alpha, from a 3x3 neighborhood for the first 4 samples) `rtx/specular_accumulate.csh` (the specular history reprojected like the irradiance, clamped to 1.5 standard deviations of the 3x3 neighborhood, up to 16 samples) and three à-trous iterations of `rtx/denoise_filter.csh` (5x5 kernel at steps 1, 2 and 4 with normal, distance and variance guided luminance weights, emissive pixels untouched); the first iteration is the next history. Pass `path_traced_light` multiplies the result by the unshaded linear albedo (zero for metal), adds the accumulated specular (the raw linear albedo for emissive pixels), encodes it into the scene with the Neutral curve and applies the chunk fade and fog from the geometry buffer (`pathtracing/radiance.fsh` through `PathTracingPipelines`), only where geometry was written. It marks the frame with `GeometryBuffer.publishTracedSpecular()`, so screen space reflections leave out the polished reflection.
- Depends on: `RayTracingResources`, `RtxComputePipeline`, `RtxImage`, `RtxDenoiseImages`, `TerrainSource`, `GeometryBuffer`, `GlossyMask`, `PathTracingPipelines`.
