# Helion Architecture: Testing Tools

Part of the [Helion architecture](../ARCHITECTURE.md).

## Testing Tools

- Debug mode (Mods → Helion → Config → Debug Mode, off by default): shows every value of `HelionDebugSnapshot` on screen without F3 and writes it as one JSON line per second to `logs/helion-debug.jsonl`, together with `toggle`, `passive` and `parity` events. GPU time per stage is only measured in debug mode (up to 64 timed passes per frame, including every `bloom_*` pass and `composite`). While it is off the debug entry, the JSON log and the timestamp queries do no work at all.
- Parity check, `J` key in debug mode: after warm-up frames on each side, captures one vanilla frame and the Helion foundation frame right after it (all effects off) within the same client tick, because the torch flicker changes the light map every tick even with ticks frozen, reads both main targets back from the GPU and reports differing pixels in chat and in the JSON log. It aborts with a message when a Helion frame could not be rendered by Helion. Use `/tick freeze` and keep the camera still: without it clouds, particles and entities move between the two captured frames, and the chat says so. A failed check reports the largest depth difference in steps of the depth format and writes `screenshots/helion_parity_differences.png` (red color only, yellow color and depth, blue depth only), so the location of a difference is known before its cause is guessed.
- `H` key: switches between Helion and vanilla rendering at runtime.
- Automated visual test: `launcher/launch.ps1 -World "Helion Visual Test" -Define helion.visualTest=true` loads a copy of a save, clears the area around the player (with `-Define "helion.visualTest=true;helion.visualTest.natural=true"` it keeps the world as it is, to photograph real terrain such as a savanna), builds a row of light blocks in front of it, switches to spectator, freezes time and weather, and photographs thirteen scenes (noon sky, sunrise sun, horizon, light blocks at noon and in the morning, so their shadows fall to the side, sunset, dusk with the orange glow just after sunset, the rising moon, night sky, the moon overhead, light blocks by night, and dawn looking toward and away from the sun) in eleven variants each (vanilla, None, Neutral, Filmic, bloom only, lighting, light only, temporal, physical sky, shadows, shadow light; the last three with volumetric clouds at Medium) into `screenshots/helion_<scene>_<variant>.png` at half resolution, then runs the parity check in every scene with ticks frozen and logs whether all pixels match vanilla (a failure is a `WARN` line). Every shot also writes a `Helion visual test` log line with the full debug snapshot as JSON, and the game closes cleanly afterwards. Run it on a copy of a world, never on a real save, because it changes blocks, time and game rules. Development runs only.
- GPU profile: `launcher/launch.ps1 -World "<save>" -Define helion.gpuProfile=true` waits 15 s after joining, hides the HUD, holds the camera and measures Helion off and every preset for 10 s each after 5 s to settle, with GPU timings on. Each step logs `Helion GPU profile <preset>: <FPS>, <measured GPU ms> [stage ms, ...]`, then the game closes. Development runs only; the world is not changed beyond normal ticking.
